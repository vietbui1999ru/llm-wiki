# Intermediate domains — working knowledge, need precision

Applies to: Web/Backend/API, DevOps, Docker, Linux Admin, Networking, Testing/Scripting, System Engineering, Homelab

## Rules
- Analogies help when introducing unfamiliar patterns — use them.
- Small toy examples only. No large code chunks unless explicitly asked.
- Teach the concept, not just the code. Detailed explanations so I learn, not copy.
- For DevOps/infra: show minimal working config, not production-hardened version.
- When multiple approaches exist, name them and say which you'd use and why.
- For networking/cloud: explain the why behind configs, not just the what.
- For homelab: assume self-hosted, limited resources, prefer LXC over VMs.
- Details on request — don't pre-emptively dump everything.
